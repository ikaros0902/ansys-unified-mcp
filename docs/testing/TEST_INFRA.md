# 測試目錄與選擇性執行

本文件說明 `tests/` 的實際目錄用途與執行入口。測試是可重用的回歸規格，不表示每次工作都要跑完整套件。

## 目錄配置

| 路徑 | 保存內容 |
| --- | --- |
| `tests/unit/` | 函式、類別與工具契約的隔離測試 |
| `tests/integration/` | 需要外部服務或應用程式環境的整合測試 |
| `tests/e2e/` | 跨元件工作流測試 |
| `tests/adversarial/` | 邊界條件、失敗路徑與安全情境 |
| `tests/canary/` | 特定風險的快速預警案例 |
| `tests/golden/` | 產品工作流與數值案例 |
| `tests/evaluations/` | MCP 問答評測定義、執行器與既有報告 |
| `tests/fixtures/` | 測試共用輸入資料 |
| `tests/mocks/` | 離線測試用的替代實作 |

這些目錄分別按驗證對象、執行方式或測試資料分工，不因名稱相近而合併。`tests/evaluations/` 是 repo 級 MCP 評測；單一技能的 `agents/skills/<module>/<skill>/evals/` 屬於該技能資源。

## 如何選擇執行範圍

- 日常變更只執行與修改程式直接相關的測試。查詢路徑或設定可先用單一測試檔，不必每次跑完整套件。
- 變更跨多個元件時，再執行相應目錄或功能群的測試。
- 合併或版本發布前，由負責人選擇完整回歸範圍。
- 整合測試需明確指定，且只在所需服務及授權可用時執行。
- MCP 評測執行器與 pytest 分開管理。報告中的歷史分數不代表目前行為，也不等於真實 ANSYS 求解驗收。

## 專案設定

`pyproject.toml` 將 `tests/` 設為 pytest 根目錄，並以 `-m 'not integration'` 排除標記為 integration 的案例。專案要求 Python 3.12 或更新版本。詳細相依與標記以 `pyproject.toml` 為準；本文件不另訂測試時間或通過率門檻。

測試可驗證程式在其 fixture、mock 和本機設定下的行為。它們不能單獨證明 ANSYS 產品 API 受支援、宿主執行成功、物理結果有效或公開散布權已取得。依賴 ANSYS 宿主或授權的行為須另行記錄環境和證據。
