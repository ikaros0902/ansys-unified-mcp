# optiSLang 判斷指南：模型品質與設計決策

本文件區分必要檢查、官方介面設定與專案經驗值。單一統計指標不能取代對驗證資料、設計空間與工程關注量的審查。

## 必要檢查

- 每個設計點保存輸入、單位、狀態、求解日誌與輸出；失敗點標為失敗/無效，不以零值代填後參與排序或訓練。
- 評估代理模型時記錄訓練/驗證策略、資料範圍、響應尺度、殘差及外部驗證誤差；以真實 solver 計算覆核候選最佳點。
- 確認輸入參數可獨立變動或明確描述相依關係；相關性警示不等同自動剔除變數。
- 代理模型在訓練設計範圍之外屬外推，需標示風險並安排真實求解點驗證；不可將 convex hull 當成所有模型的精確可信邊界。

## 指標的適用方式

CoP、交叉驗證誤差、TSI、相關係數與 VIF 的計算與解釋依模型類型、抽樣、資料品質和 optiSLang 版本而定。沒有官方或專案接受準則時，報告原始值、樣本數、計算方式和不確定性，不套用固定的 0.80 CoP、5% TSI、0.85 相關係數或 VIF=5/10 作普遍硬門檻。

DoE 點數取決於維度、非線性、交互作用、噪聲、失敗率及計算預算；`N >= 10*k` 僅能作粗略規劃經驗值，不能保證足夠。必要時以序貫補點、留出驗證與響應穩健性決定是否繼續。

## 專案經驗值與決策

歷史 CoP/TSI/VIF 分段僅是專案篩查參考，不是官方保證。若用於某類模型，須記錄案例、版本、驗證集、目標誤差與實際覆核結果。高維或低預測能力模型不自動禁止分析；先縮小問題、增加有信息量的樣本或使用可解釋的低維參數化，再以工程關注量決定是否適合尋優。
