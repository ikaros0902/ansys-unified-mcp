# 轉檔驗證與驗收紀錄

## 驗證必須對應交付物

`Save` 成功、檔案存在、檔頭正確與 JSON 的 `verified=true` 各自只是一部分證據。要重新開啟實際輸出，量測來源與匯入結果，並審查判定條件；驗證腳本不能只重述自身旗標。

最小 manifest：來源組立與階層路徑、元件名／料號、代表 occurrence 與重複數、分類依據、輸出格式與絕對路徑、bytes、SHA-256、來源／匯入量測、誤差、容差依據及 unresolved 狀態。沒有材料／密度時，不把體積當成已知質量。

## 幾何比對

- 分開記錄 body、solid、open shell、face，避免把 body 數當成封閉實體數。
- 重開後先比 body 數，再比總表面積、可計算體積與外形尺寸；有多種幾何時也要逐元件／子樹覆蓋比對，避免總量掩蓋遺漏。
- 相對誤差可用 `abs(a-b)/max(abs(a),abs(b),epsilon)`，epsilon 應符合量綱與尺度。零體積曲面不做除零；體積計算失敗與零體積分別記錄。
- 記錄計算失敗的 body 清單及數量。部分可計算體積只作輔助指標；不能用略過失敗後的加總宣稱全模型質量一致。
- 原生 API 可能回傳 occurrence 形狀或 master 幾何。尺寸應在相同座標框架比較；已知旋轉不能靠放寬容差處理。單一零件可比 `body.GetMaster().Shape` 的本地幾何；整個子裝配體要保留內部 placement，不能逐 body 去掉 placement 再宣稱取得組立外框。
- 把 bbox 三軸排序僅能消除軸排列差異，不能消除任意角度旋轉。必要時明確轉換到相同座標框架。

量測 API 在本次 V251 可用 `body.Shape.SurfaceArea`、`body.Shape.Volume`、`body.Shape.GetBoundingBox(Matrix.Identity)`，bbox 的 `.Size.X/Y/Z` 為 SI 長度。`Shape` 可為 `Body` 或 `TrimmedSpace`，不要假設它們具有相同成員。

## body 數改變的處理

預設保持未通過並調查，不因其餘指標接近就直接接受。STEP 可能拆分／合併 shell、改寫 face 分組與名稱，必須保留拓撲差異。

本次 SP7 的來源 714 bodies，重開 STEP 為 769 bodies。補強證據是：來源與匯入的 19 個對應子裝配體全數匹配、沒有未對應群組，兩邊群組加總分別涵蓋全部 714／769 bodies 的面積，各組面積差均在本案容差內，且總面積與外形尺寸亦符合。這支持本案的幾何轉檔交付，**不支持拓撲不變或封閉可求解實體的宣稱**。

STEP 結構可再查 `ISO-10303-21;`／`END-ISO-10303-21;`、entity ID 唯一性與參照完整性；這些檢查不能取代幾何比對。`BREP_WITH_VOIDS` 也是實體表示，不能只數 `MANIFOLD_SOLID_BREP`。

## 驗證失敗與檔案管理

- 每件各自判定；一件失敗不能標示整批通過。
- 未確認分類或未通過的產物放待確認目錄並保留原因，與正式素材分開。
- 不覆寫不同內容的同名檔；複製後核對雜湊。移除本次產生的錯誤產物前確認精確路徑及來源，勿操作使用者原始模型。
- 有活躍程序或工具 session 時，監看原 handle；觀察逾時不等於轉檔終止。沒有證據時不要重開大型模型或終止使用者程序。
- 交付紀錄明確區分「轉檔完成」、「簡化完成」、「修復為封閉幾何」與「求解器可用」。
