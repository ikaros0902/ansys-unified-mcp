# 進階 Skill 撰寫流程

本流程適用於為單一產品或可重現工程任務新增／改寫專項 Skill。基礎 Skill 提供共用路由；專項 Skill 只承載會改變該任務決策的知識。

## 定義 Skill 的工作範圍

先從使用者需求和現有專項 Skill 抽出：觸發情境、輸入與必要前提、預期輸出、成功條件、不可推論的事項。Description 說明 Agent 何時應載入此 Skill；入口正文說明最短可用流程、重要判斷、支援邊界及 references 路由。保留使用者選定的產品、版本和交付範圍。

## 用來源證據形成指引

1. 依 [來源查找與文件限制](source-routing.md) 找到官方文件的精確產品 release、API 和例子，並用 [程式碼地圖](repository-map.md) 追出實際 MCP 呼叫鏈及相關測試。
2. 對每個 API 指引，寫出宿主／介面和證據層級；不確定參數型別、簽名或版本支援時，明說待核對並指出下一個查證位置。
3. 對每項工程判斷寫清適用分析、單位、必要輸入、公式／判斷法、嚴重程度和來源；把必要條件、官方建議和 project heuristic 分欄或標籤區隔。
4. 把 API schema、版本差異、長流程及故障對照放入單一職責的 reference。入口只連到當前任務會用到的檔案；不要重印手冊、既有工具 schema 或其他 Skill 的完整內容。
5. 如內容提出 MCP 工具需求，先清點現有工具能力與輸入／輸出，再說明缺口；工具設計採明確 schema、單位和可操作錯誤。對大量 API 考慮「搜尋後精確執行」的模式，但需符合本 repo 的工具註冊、session 和回傳契約。

## 驗收方式

- 對應來源與內部連結有效；API 能在指定版本／介面找到，或明確標成待查。
- 用 2–3 個具體代表案例走讀 Skill：至少涵蓋正常流程、版本／輸入歧義或失敗處理其中一項。案例需能觀察到 scoping、單位、結果來源或支援邊界是否判斷正確；不要只比對標題或文句。
- 程式或工具契約有改動時另跑相應離線測試；只有使用者授權且環境可用時才跑真機驗收，不能用 mock 替代。
- 更新專案 `agents/skills/README.md` 路由索引及必要的領域來源矩陣；確認入口行數不超過專案 200 行限制，無死連結、TODO scaffold 或不實支援宣告。
