# Anti_Pattern 檢查清單樣板

> 用途：審查既有 Loop 時，逐項比對常見 Anti_Pattern，於損害發生前發現並修正設計缺陷。
> 建議存放位置：專案內 Loop 設計文件旁（例如 `loops/<loop-name>/anti-pattern-checklist.md`）。
> 填寫說明：針對每項 Anti_Pattern，比對「可觀察症狀」是否出現於待審查的 Loop；若出現，勾選該症狀並依「改善建議」修正。將 `<...>` 佔位符替換為實際觀察內容即可，勿寫入任何特定工具的專屬指令或語法。

## Anti_Pattern 1：Loop 過度複雜

> 說明：Loop 的階段、Sub_Agent_Role 或分支過多，導致難以理解、維護與追溯。

可觀察症狀（勾選代表症狀出現）：

- [ ] Sub_Agent_Role 數量超過 4 個。
- [ ] 單一 Loop 同時承擔多個彼此無關的目標。
- [ ] 階段之間的輸入/輸出關係難以一眼看懂或無法追溯。
- [ ] `<其他觀察到的複雜化症狀>`

改善建議：

- 將 Sub_Agent_Role 精簡至 4 個以內，超出者拆分或合併。
- 依單一職責拆分為多個較小的 Loop，每個 Loop 只服務一個明確目標。
- 明確定義各階段的輸入與輸出，使資料流可追溯。

## Anti_Pattern 2：Verification_Condition 過弱

> 說明：停止或完成條件過於寬鬆或模糊，使 Loop 無法客觀判定任務是否真正完成。

可觀察症狀（勾選代表症狀出現）：

- [ ] Verification_Condition 缺失，或僅以主觀描述（如「看起來沒問題」）判定完成。
- [ ] 未定義明確的停止條件，Loop 可能無限執行。
- [ ] 驗證僅檢查是否有輸出，未檢查輸出是否正確。
- [ ] `<其他觀察到的驗證薄弱症狀>`

改善建議：

- 為 `verify` 階段定義客觀、可自動判定的停止條件。
- 補上明確的成功判準與失敗退回機制。
- 讓驗證檢查產物的正確性，而非僅檢查產物是否存在。

## Anti_Pattern 3：忽視成本管理

> 說明：未設定成本或頻率上限，Loop 在自動執行下可能累積不受控的資源消耗。

可觀察症狀（勾選代表症狀出現）：

- [ ] 缺少 `budget` 欄位，或未設定任何成本／頻率上限。
- [ ] `budget` 值為無效值（非數值或小於等於 0）。
- [ ] 觸發頻率未估計，無法評估累積成本與風險。
- [ ] `<其他觀察到的成本失控症狀>`

改善建議：

- 為 Loop 補上 `budget` 欄位，設定大於 0 的成本或頻率上限。
- 估計 Automation_Trigger 的執行頻率，據以評估累積成本。
- 為高頻或高成本 Loop 加上上限保護與告警機制。
